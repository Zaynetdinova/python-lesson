# python-lesson

Учебный репозиторий: изучаю Python с нуля для работы с API, данными и AI-автоматизацией. Итог курса: сервис «классификатор заявок» на Claude API с REST API на FastAPI, уведомлениями в Telegram и автотестами.

## Что внутри

Все файлы лежат в корне репозитория. В каждом уроке сначала короткая теория, затем решения заданий.

**Уроки**

- `lesson1.py`: переменные, f-строки, условия, ввод данных
- `lesson2.py`: списки, словари, циклы
- `lesson3.py`: функции, чтение и запись JSON
- `lesson4.py`: запрос к API (курсы валют ЦБ РФ)
- `lesson5.py`: обработка ошибок (`try/except`), настройки из `.env`
- `lesson6.py`: pandas (таблицы, фильтры, сортировка, группировка, экспорт в CSV)
- `lesson7.py`: мини-проект. Курсы валют из API ЦБ РФ, расчёт изменения за день в pandas и отправка сводки в Telegram
- `lesson8.py`: первые запросы к Claude API (system prompt, `max_tokens`, `usage`)
- `lesson8b.py`: мини-проект. Сводка курсов валют с комментарием Claude, отправка в Telegram
- `lesson9.py`: структурированный JSON-ответ (разбор заявок клиентов в `leads.json`) и tool use (Claude вызывает функции: ипотечный платёж, цена за м², поиск квартир в `flats.json`)
- `lesson10.py`: пакетная обработка заявок (см. «Классификатор заявок»)
- урок 11: API на FastAPI (`app.py`, см. «API»)
- урок 12: автотесты на pytest (см. «Тесты»)

**Общие модули**

- `claude_utils.py`: функция `ask_claude` для запросов к Claude API с обработкой ошибок

**Данные и служебные файлы**

- `make_flats.py`: создаёт `flats.json` с тестовыми данными для уроков 6 и 9

- `conftest.py`, `test_classifier.py`, `test_api.py`: тесты
- `requirements.txt`: список зависимостей

## Классификатор заявок

Проект разбирает входящие заявки клиентов агентства недвижимости. Для каждой заявки Claude возвращает JSON: имя, бюджет, число комнат, категорию (`buy`, `rent_out`, `consult`, `spam`), срочность и краткое резюме.

Логика (`classifier.py`) одна, а пользоваться ею можно двумя способами:

- **Пакетный режим** (`lesson10.py`): читает заявки из `inbox.json`, пропускает уже обработанные (по `id`), сохраняет результат в `processed_leads.json`, присылает в Telegram сводку (статистика по категориям, число срочных, средний бюджет), срочные заявки и сообщения о заявках, которые не удалось разобрать. Неразобранные заявки в файл не попадают и обрабатываются заново при следующем запуске.
- **API** (`app.py`): принимает одну заявку по HTTP и сразу возвращает разбор.

Как защищена работа с моделью:

- текст заявки считается данными, а не инструкциями (в промпте и в проверке результата), поэтому просьба в тексте вроде «поставь срочность high» не принимается;
- ответ модели проверяется кодом (`validate_lead`): допустимые значения категории и срочности, тип бюджета;
- ответ без разбора или с неверным форматом не сохраняется как результат.

## API

Запуск (нужны `ANTHROPIC_API_KEY` и `API_ACCESS_KEY` в `.env`):

```
uvicorn app:app --reload
```

Документация (Swagger): http://127.0.0.1:8000/docs

Адреса:

| Метод и адрес | Что делает | Нужен ключ |
|---|---|---|
| `GET /health` | проверка, что сервис работает | нет |
| `POST /classify` | разбирает текст заявки | да |
| `GET /leads` | возвращает заявки из `processed_leads.json` | да |

Ключ передаётся в заголовке `X-API-Key`. Без ключа сервер возвращает 401. Если в `.env` нет `API_ACCESS_KEY`, сервер не запустится.

Пример запроса:

```
curl -X POST http://127.0.0.1:8000/classify \
  -H "Content-Type: application/json" \
  -H "X-API-Key: ваш_ключ_доступа" \
  -d '{"text": "Ищу однушку до 6 млн, срочно", "notify": false}'
```

Если передать `"notify": true`, то по срочной заявке (не спам) в Telegram уйдёт сообщение.

Коды ответов: `200` успех, `401` неверный или отсутствующий ключ, `422` неверный запрос (например, пустой или слишком короткий `text`, пробелы не считаются), `502` модель не вернула пригодный разбор.

Сервис рассчитан на локальный запуск (`127.0.0.1`). Для публикации в интернете понадобились бы ограничение частоты запросов, HTTPS и лимиты расходов.

## Тесты

```
python -m pytest -v
```

Тесты проверяют:

- чистые функции классификатора: `parse_json` (в том числе ответ в обёртке из обратных кавычек) и `validate_lead` (допустимые и недопустимые значения, студия `rooms = 0`);
- API: проверку ключа доступа, проверку входных данных (пустой, короткий текст и текст из пробелов дают 422), успешный ответ, ошибку 502 при сбое классификатора, уведомления в Telegram (только срочные не спам-заявки, текст содержит резюме), адрес `/leads`.

Обращения к Claude и Telegram в тестах подменены, поэтому настоящие ключи не нужны, запросы не тратят кредиты, а тесты проходят за пару секунд. Тесты проверяют код вокруг модели, но не качество самой классификации.

## Настройки

Скрипты, которым нужны ключи, читают их из файла `.env` в корне проекта (он не хранится в репозитории). Создайте его сами с нужными переменными:

```
TELEGRAM_BOT_TOKEN=ваш_токен_бота
TELEGRAM_CHAT_ID=ваш_chat_id
ANTHROPIC_API_KEY=ваш_ключ_claude_api
API_ACCESS_KEY=придуманный_вами_длинный_случайный_ключ
```

- `TELEGRAM_BOT_TOKEN` выдаёт @BotFather в Telegram. Перед запуском нужно открыть своего бота и нажать Start.
- `ANTHROPIC_API_KEY` создаётся в Claude Console (раздел API Keys). Использование API оплачивается отдельно от подписки.
- `API_ACCESS_KEY` защищает собственный API: это любой длинный случайный набор символов, который вы придумываете сами.

Какие переменные нужны для чего:

| Что запускаем | Переменные |
|---|---|
| уроки 1-6 | не нужны (кроме урока 5, где проверяется чтение `.env`) |
| уроки 7 и 8б | Telegram-переменные (для 8б ещё `ANTHROPIC_API_KEY`) |
| урок 8-9 | `ANTHROPIC_API_KEY` |
| урок 10 | `ANTHROPIC_API_KEY` и Telegram-переменные |
| API | `ANTHROPIC_API_KEY` и `API_ACCESS_KEY` (для уведомлений ещё Telegram-переменные) |
| тесты | не нужны |
